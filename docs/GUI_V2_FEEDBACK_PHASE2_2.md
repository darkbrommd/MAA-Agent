# GUI 2.0 实机反馈修正说明（Phase 2.2）

本轮处理 2026-11-26 凌晨实机反馈。仍在 `codex/gui-v2-pyside6` 功能分支工作；默认 Tk 入口、生产 Agent、`app/agent.py`、VPN/代理和真实配置均不修改。每个可交付节点用 Git 提交保存，配置写入继续保留 `.bak`。

## 本轮范围

1. 确认顶部“小柒 / Dark”来自真实 `maa_instance_aliases` 还是预览占位；界面不得把演示名称写死。
2. 修正日程日期分隔线与文字重叠；统一页面正文、辅助文字、分组标题和左侧导航字号层级。
3. 总览“未来 36 小时”改用日程时间轴一致的状态色与卡片语义，并加入自然日日期分隔；窄分栏保持两行信息，不挤成三行。
4. 最近事件为空时显示明确占位语句，不让空白区域看起来像加载失败。
5. 修正计划到点但尚无 `schedule_run_status=running` 时仍显示“即将执行”、并从总览消失的问题。到点后的短确认窗口显示“等待启动确认”，只有真实运行记录才显示“正在进行”。
6. 内存排行同时核对单进程与同名应用汇总口径；界面采用更接近任务管理器的应用汇总，并标出进程数量。
7. 日志中心用面向用户的名称展示：例如“运行日志（agent.log）”“决策日志（decision.log）”，底层文件名不变。
8. 只读检查用户在 MAA 运行时停止并重新启动 Agent 的现有日志与状态，确认是否正确保留日志 offset、计划监督和运行状态；不再次启停生产进程。

## 验收

- 日程和总览日期分隔线不穿过文字，100%–175% 缩放均成立。
- 总览与日程对同一 occurrence 使用相同状态、颜色和别名；到点计划不会直接消失。
- 未来计划窄栏不因按钮和长状态文字形成三行；必要时提供 tooltip 查看完整说明。
- 无最近事件时有占位；有新日志增量时占位自动消失。
- 完整回归、175% GUI 专项、后台零 PySide6 导入和远端 Windows CI 通过。

## 实施结果

- 顶部的 `Dark` 与 `小柒` 已确认来自生产配置 `maa_instance_aliases`，不是预览占位符；本轮没有改动真实配置。
- 日期分隔线改为按文字实际渲染宽度避让；正文、辅助文字、导航项和分组标题字号重新拉开层级。
- 总览未来计划加入自然日分隔，复用日程的灰/黄/绿/红状态语义；卡片固定两行，窄栏用省略与 tooltip，不再挤成三行。
- 到点计划保留两小时查询窗口，并在短暂启动确认期显示“等待启动确认”；已有运行证据时，总览与日程统一显示“正在进行”。
- 内存排行改为应用总量：普通同名程序合并并显示进程数；MAA 按 `MAA1`/`MAA2` 实例继续分开；MuMu/Nemu 同族进程合并为 MuMu。

- 2026-11-26 本地验收：完整回归 193 项通过，175% GUI 专项 32 项通过，`compileall` 通过，后台入口零 PySide6 导入专项通过。
