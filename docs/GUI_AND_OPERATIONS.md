# MAA Agent 管理器与运行说明

## 日常入口

双击 `MAA-Agent-GUI.bat` 打开统一管理器。它包含：

- **运行状态**：Agent PID/运行时长、已配置的 MAA、MuMu、CPU、内存、磁盘、未来计划和最近日志；
- **计划与本次例外**：查看未来 7 天计划，并对某一次计划执行“跳过 / 改时 / 撤销”；
- **时间策略**：集中调整检查间隔、开机宽限、进程缺失、错误无进展、计划漏跑、未响应、内存压力、代理和心跳时间；
- **全部配置**：查看和编辑 `config.json` 的全部键值，Bark/DeepSeek 密钥默认遮罩；
- **日志**：查看 `agent.log` 和 `decision.log` 最近内容。

“设置 → 启用系统代理健康检查”可以临时关闭外网探测。关闭后 Agent 不读取系统代理配置，也不访问探测地址；MAA、资源、日程、公告等其他监控继续运行。该开关与“高级时间策略”中的同名开关同步，保存后下一轮自动生效。

设置页底部显示当前版本、作者 Taylor Yu 和可点击的 GitHub 主页链接。

窗口最小化或点击关闭按钮后会进入系统托盘，后台 Agent 不会因此停止。托盘菜单可以重新打开管理器、启动/停止 Agent，或仅退出管理器。

## Windows 辅助脚本

- `tools/windows/start_agent.bat`：无控制台窗口启动当前目录的 Agent；
- `tools/windows/stop_agent.bat`：无控制台窗口请求当前目录的 Agent 正常退出；
- `tools/windows/emergency_stop_agent.bat`：先校验目标确实是当前目录的 `agent.py`，再在必要时强制停止；
- 其他维护、测试和兼容入口见 [`tools/windows/README.md`](../tools/windows/README.md)。

所有入口都根据脚本自身位置计算项目根目录，不依赖固定安装路径，因此复制目录后仍会使用同一份程序、配置和状态。

## 单实例与停止安全

当前版本使用 Windows 命名互斥锁防止同时启动两个新版实例。为了兼容旧版，它还会检查其他 `MAA-Agent*` 目录，但只把以下进程视为 Agent：

1. 进程本身必须是 `python.exe` / `pythonw.exe`；
2. Python 实际执行的第一个脚本必须精确为 `agent.py`；
3. 脚本父目录名必须以 `MAA-Agent` 开头。

VS Code 打开 `agent.py`、PowerShell 搜索代码、日志里出现路径，都不会再被误判为正在运行的 Agent。

停止时会同时校验 PID、进程创建时间和脚本路径。PID 文件陈旧或 PID 已被别的程序复用时，不会结束无关进程。

## 时间设置的边界

“计划与本次例外”只改变 Agent 对某一次计划的监督预期。例如把今晚 22:00 标记为跳过，含义是今晚未运行时 Agent 不报警；它不会修改 MAA 自身定时器。

MAA1/MAA2 的长期真实执行时间仍在 MAA 的“设置 → 定时执行”里修改。Agent 优先读取各实例的 `config\gui.new.json`，失败时读取 `.bak`，最后才使用 `config.json` 中的备用时间表。

“时间策略”中的数值是监控判断与采样时间。保存后，运行中的 Agent 会在下一轮重新读取配置，无需重启。

## 推荐日常操作

1. 平时只打开 `MAA-Agent-GUI.bat` 查看状态；
2. 需要重启监控时使用 GUI 的“重启 Agent”；
3. 需要临时取消一次漏跑判断时，在“计划与本次例外”操作；
4. 修改配置后观察底部状态提示确认保存；`config.json.bak` 会保留上一次配置；
5. 只有正常停止 20 秒仍无响应时才使用强制停止。

## 回归测试

运行 `tools/windows/run_regression_tests.bat`。当前生命周期测试重点覆盖：

- 编辑器/PowerShell 命令行带 `agent.py` 不得触发重复进程；
- Python 3.14 虚拟环境保留的启动器父进程不得被当成第二个 Agent；
- 真正的 Python Agent 仍能跨目录识别；
- 同时启动第二个新版实例会被命名互斥锁阻止；
- 正常停止后 PID 与运行记录被清理；
- GUI 能创建全部标签页、读取配置、计划和状态。
