# GUI 2.0 最终界面修整

本轮根据 2026-11-26 的实机截图和设计示意，收束 GUI 2.0 的顶部布局与日程翻动范围。先记录最终交互，再修改代码，避免后续继续在不同版本之间摇摆。

## 顶部区域

- 总览保留 Agent、MAA 和 MuMu 状态，以及启动、停止和重启 Agent 的操作入口。
- 状态胶囊放在总览内容中，不再作为所有页面共用的固定顶栏。
- 日程管理、资源监控、公告中心、日志中心和设置不显示顶部状态栏，页面内容直接上移使用这部分空间。
- 不通过缩小字号解决拥挤；窗口较窄时仍保持文字可读，并由总览内部布局承担状态区域的宽度变化。

## 日程翻动

- 初次打开仍加载所选日期前后各 3 天，保证当前时间附近有完整上下文。
- 滚动到时间轴边缘继续查看时，每次只向对应方向增加 1 天，不再一次增加 2 天。
- 保留现有滚轮手势锁、旧请求丢弃、滚动锚点和最多 31 天边界，避免触底加载后跳动或重复加载。
- 普通鼠标滚轮每格移动约 48px，避免一次跨过大半张卡片；触控板的像素级平滑滚动保持原样。

## 资源记录频率

- 正常记录仍按原间隔写入；刚进入异常、异常类型变化或数值明显变化时及时写入。
- 异常状态持续且变化很小时，由每分钟一条放宽为每 5 分钟一条，减少 00:00、00:01 这类重复卡片。
- 这个间隔只影响资源历史记录，不改变手机提醒冷却，也不修改 Agent 的事故判断。

## 同批界面细节

- 总览计划卡去掉重复的完成描述。
- 总览去掉底部更新时间，让左右内容区使用完整高度；“隐藏这些记录”改为“清除总览记录”。
- 日程说明使用：“开关和日期修改只影响当次监测，不会影响 MAA 本身的计划执行。”
- 设置页说明只保留：“改好后点击右下角保存就可以。”
- 高级设置中以分钟为单位的输入使用整数。
- 资源日期日历使用橙黄、绿色和灰色状态点；通知测试页按设计稿整理为样例网格、预览和真实 Bark 通道测试。

## 验收

- 切换到总览时能看到状态和 Agent 操作；切换到其他页面后顶部区域消失，内容立即上移。
- 页面懒加载、当前页面状态和刷新频率不受影响。
- 日程触顶或触底一次只扩展 1 天，加载期间继续滚轮不会在完成后补滚。
- 100%、125%、150% 和 175% 缩放下无字体挤压、横向滚动条或按钮遮挡。
- 默认 Tk 界面、生产 Agent、真实配置和 `app/agent.py` 不改动。

## 本轮完成结果

- 全局顶栏不再承载状态胶囊；Agent 操作栏只在总览显示，切换到其他页面后整条区域隐藏。
- Agent、已配置的 MAA 和 MuMu 状态胶囊已移入总览标题行，保留原有进程快照刷新和状态颜色。
- 日程触边扩展由每次 2 天缩为每次 1 天，滚轮尾部锁和滚动锚点保持不变。
- 普通鼠标滚轮步长固定为较短距离，不再跟随 Windows 的较大滚动行数一次跨过多张卡片。
- 资源历史增加稳定异常降频：异常刚发生或明显变化时立即记录，持续无变化时每 5 分钟记录一次。
- 资源监控使用与日程一致的日期框，并继续保留前一天、后一天和回到今天。
- 资源日历在后台读取整月记录：异常日期显示橙黄点，正常日期显示绿点，无记录日期显示灰点。
- 总览移除常驻更新时间，完成状态不再重复显示“已完成”，清理按钮改为“清除总览记录”。
- 日程说明、设置说明和高级设置整数分钟按最终文案统一。
- 通知测试页提供 MAA、Bark、内存、磁盘、网络、窗口、计划、Agent 和官网维护样例；单 MAA 配置自动隐藏 MAA2 样例。
- 深色模式进一步拉开等待运行、已经完成和停止监测三种卡片底色。
- 175% 缩放离屏检查确认：总览控制区和状态行未重叠；日程页面移除顶栏后正常上移。
