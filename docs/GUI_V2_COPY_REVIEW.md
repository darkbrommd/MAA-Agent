# GUI 2.0 用户文案复核

本轮只修正用户能看到的文字和相关页面结构，不改变 Agent 业务逻辑、真实配置、生产进程或网络环境。

## 文案原则

1. 先说这个功能能做什么，再说用户什么时候需要操作。
2. 不要求用户理解代码、配置文件、后台读取流程或内部模块名。
3. 删除“为了安全不会……”“只有点击……才会……”“下一轮读取……”等反复解释边界的防御性话术；确实可能产生费用、通知或数据变化时才保留简短提醒。
4. 普通页面避免使用“实例、原子保存、代理健康检查、配置草稿、config.json”等开发术语。
5. 保留用户已经认识的产品名：MAA、MAA1/MAA2、Agent、MuMu、Bark、AI。
6. 错误提示回答两件事：哪里没填对，以及该怎么改。

## 本轮范围

- 删除设置页“全部配置”分组；确有必要的时间和检查选项留在“高级设置”。
- 重写设置页、首次使用向导和托盘提示。
- 复核总览、日程、资源、公告、日志及全局状态栏中的可见文字。
- 不改日志原文、开发文档、测试名称和代码内部字段名。

## 验收标准

- 设置页不再出现 `config.json`、原子保存、下一轮读取等实现说明。
- 普通用户无需了解“实例”“代理健康检查”等术语也能判断开关用途。
- 提示语简短，不重复保证“不会修改某某”；只有真实推送等有外部影响的操作保留确认。
- 页面删除一组后，二级目录、状态保留和测试计数同步更新。

## 实施结果

- 设置页删除“全部配置”，六个目录改为“常规与程序 / 提醒设置 / 手机通知与 AI / 高级设置 / 通知测试 / 关于”。
- 设置页和首次使用向导移除 `config.json`、实例、代理健康检查、下一轮读取等开发用语；保存结果只显示“已保存”。
- 日程页将“监督预期、例外、启动证据、终态”等改为“这次提醒、恢复计划、确认启动、还没确认结果”。
- 资源页将“资源白名单、异常采样、缓存命中、单进程快照”等改为“高占用程序、内存过高记录、程序明细”。
- 公告页将“增量更新 / 全部重拉 / 本地缓存”改为“检查新公告 / 重新获取全部 / 已保存”。
- 日志页删除“增量读取、字节”等实现信息；总览页不再显示 PID 或真实日志文件名。
- 新增用户文案回归检查，防止这些内部术语重新进入界面。2026-11-26 完整回归 204 项、175% GUI 专项 42 项通过。
