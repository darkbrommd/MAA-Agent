# MAA Agent 2.0 Phase 1 实机反馈修整记录

## 本轮定位

本轮只修整 Phase 1 已完成的 PySide6 预览界面，不进入总览、公告、日志、设置和托盘等后续阶段。新版仍通过 `launcher.py --gui-v2` 单独启动，默认 Tk 界面、后台 Agent 和当前生产进程都不替换、不停止。

## 用户反馈与已确认原因

1. **字体与背景不协调**
   - 当前 QSS 给所有 `QWidget` 强制绘制页面底色，容易让容器、弹窗和自绘控件出现不该有的实色块。
   - 应用没有在 Qt 入口统一设置 Windows 中文界面字体；Delegate 又分别硬编码字体，字号和粗细不够统一。
2. **日程状态表达比旧版弱**
   - 旧版中“运行中、最近下一次、失败、已结束/关闭”会改变整张卡片底色，并配合左侧状态色条。
   - 当前 PySide6 版只有失败卡片改变底色，运行中和下一次主要靠文字颜色，扫一眼不够直观。
3. **“调整本次监督预期”退化成总入口**
   - 旧版每张卡片直接提供监测开关和“修改时间”；当前版本要求先选中，再点顶部入口，再选择动作，步骤更多，也不清楚正在操作哪张卡。
4. **时间轴触底会顿一下并继续冲出很远**
   - 当前扩展日期后使用 `beginResetModel/endResetModel` 重置整个列表，再把锚点强制滚到屏幕中央。
   - 鼠标滚轮的惯性事件仍在继续时，重置和居中会叠加成明显跳动。

## 本轮实施内容

### 1. 字体和背景

- 在 Qt 应用入口统一设置 `Microsoft YaHei UI`，数字和时间仍在自绘区域使用 `Segoe UI`。
- 页面底色只交给主窗口、页面和明确命名的容器，不再给所有子 `QWidget` 强制刷底。
- 补齐列表 viewport、弹窗、按钮悬停/选中、状态标签在深浅主题下的明确颜色。

### 2. 日程卡片状态

- 保留四类明确语义：失败暗红、运行中暗黄/浅黄、最近下一次暗绿/浅绿、已结束或关闭低强调灰。
- 每张卡保留左侧状态色条，并增加小型状态标签；颜色只表达运行语义，不作装饰。
- 明确失败仍优先于后续笼统完成信号，不修改 `app/agent.py` 的判定逻辑。

### 3. 单条计划直接操作

- 每张卡直接显示统一 Toggle：开启表示本次纳入 Agent 监督，关闭表示本次不判漏跑。
- 每张卡提供“修改时间”；存在一次性例外时提供“撤销例外”；失败卡继续提供“查看错误”。
- 删除顶部笼统的“调整本次监督预期”入口，避免先选中再猜测目标。
- 所有热区继续由 `compute_card_layout()` 同时提供给 `paint()` 和 `editorEvent()`，保证 100%/125%/150% 缩放下点击位置一致。
- 这些操作只写 `schedule_overrides.json`，不修改 MAA 自己的定时器。

### 4. 触底扩展稳定性

- 日期扩展优先使用 Model 的头部/尾部增量插入，不重置已有列表。
- 向下扩展时保持当前滚动值；向上扩展时按新增内容高度补偿，保持原卡片在屏幕中的位置。
- 一次真实滚轮手势只触发一次扩展，加载期间和短暂冷却期间忽略后续惯性触底事件。
- 用户主动选择日期或点击“回到现在”时仍可重新定位到目标时间附近。

## 验收标准

- 深色和浅色下中文字体、页面底色、卡片、弹窗无明显色块或文字发虚问题。
- 不打开额外总对话框即可在目标卡片上开关监督、修改时间、撤销例外或查看错误。
- 四种计划状态可以只看卡片底色和标签快速区分。
- 连续滚到时间轴底部扩展日期时，原视图不居中跳转，不因惯性继续滚出一大段。
- `app/agent.py` 无改动；默认入口仍为 Tk；`--maa-agent-background` 路径仍不导入 PySide6。
- 全量回归测试、Qt offscreen 测试、完整 Windows 打包和 GitHub Actions 继续通过。

## 完成记录

2026-11-25 已完成本轮修整：

- `app/gui/main.py`：统一设置 Windows 中文界面字体。
- `app/gui/themes/`：移除对子控件的全局背景强刷，增加运行中、下一次、已结束卡片底色及动态状态胶囊样式。
- `app/gui/main_window.py`：Agent、MAA、MuMu 胶囊按运行、停止、混合和读取失败切换底色。
- `app/gui/components/timeline_delegate.py`：恢复整卡状态底色、左侧色条、卡内 Toggle、修改时间、撤销例外和查看错误；所有绘制与点击仍共用一套布局矩形。
- `app/gui/models/schedule_model.py`：日期窗口扩展改为头尾增量插入；稳定键包含实例、原始时间、timer id 和配置，避免重复计划恢复错位。
- `app/gui/pages/schedule.py`：删除顶部笼统入口；一次性操作改为单线程保存队列并防重复提交；请求模式和滚动锚点绑定到 request id；触底直接由 Wheel 和滚动值共同判断；惯性滚轮按最后事件静默释放，切换日期会主动解除旧锁。
- `tests/test_z_gui_v2.py`：新增主题、共享热区、增量插入、上下扩展锚点、已在底部的滚轮触发、请求取代解锁、重复计划稳定键、override 添加/替换/撤销等测试。
