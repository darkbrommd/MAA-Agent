# GUI 2.0 自适应与交互修整记录

本轮根据 2026-11-25 的实机截图与 10.5 秒开关操作录像，集中修正日程、资源页和折叠导航的交互问题。这里先写清预期，再改代码，避免修完后只剩下零散聊天记录。

## 看到的问题

1. 日程卡片的开关、时间和标题没有落在同一条视觉基线上，时间看起来偏斜。
2. 点击导航项、工具栏按钮后会出现 Qt 默认白色虚线焦点框；时间轴还会额外绘制整张卡片的选中边框。
3. 时间轴触底加载时会暂时拦截滚轮，但原来的 280ms 静默计时不足以覆盖触控板或高分辨率滚轮的惯性尾巴。加载完成后，尾部事件可能继续滚动，造成视图突然越过多张卡片。
4. 卡片开关要等待异步写盘与列表刷新后才改变，缺少点击动画，视觉上像先卡住再跳变。
5. 日程卡片和资源异常卡片始终铺满视口；窗口越宽，中间空白越长，按钮被推到很远。列表宽度还会因竖向滚动条出现而产生横向滚动条。
6. 资源图表和异常采样区的高度比例固定，不能随着窗口和用户偏好调整。
7. 左侧导航折叠后只剩中文首字，辨识度低，也容易把“日程”和“日志”混淆。

## 本轮做法

- 日程卡片统一首行基线：开关、时间和实例名横向对齐；状态信息留在第二、三行。
- 普通鼠标点击不再显示白色虚线；时间轴本身不保留无业务意义的卡片选中态。键盘焦点仍可存在，但不绘制 Windows 默认虚线框。
- 触底扩展改为一个完整的滚轮手势锁：加载期间和同方向惯性尾部全部吞掉；加载完成后清理已排队滚轮事件，等手势安静后再解锁。反方向滚动仍可立即退出锁定。
- 开关使用约 140ms 的平滑动画并乐观响应；后台保存失败时动画回滚，业务语义仍只写一次性监督例外，不修改 MAA 定时器。
- 列表项目宽度不再引用旧视口宽度，明确关闭横向滚动条；中等窗口占满可用宽度，超宽窗口只缓慢增长并设置合理上限，减少“贯穿整屏的长条”。
- 资源图表与异常采样列表之间改为可拖动的纵向分隔条；窗口缩放时两区自动分配，拖动比例保存到 `state/gui_state.json`。
- 为六个导航项加入仓库内置线性 SVG 图标。展开时显示“图标 + 文字”，折叠时只显示居中图标和提示，不再截取中文首字。

## 验收标准

- 100% / 125% / 150% 缩放下，日程时间、开关、标题不歪，按钮热区仍与绘制位置一致。
- 日程与异常采样列表不出现横向滚动条；宽屏下卡片不会无限拉成长条。
- 触底加载时继续滚动三次，加载完成后视图不补滚三次，也不跳过刚加载的内容。
- 点击开关立即看到平滑移动；保存失败能回到原状态。
- 导航和常用按钮点击后无白色虚线；折叠导航仅显示清晰图标。
- 资源页上下分区可拖动，重新打开页面后恢复上次比例。
- `app/agent.py`、生产配置、真实 `state/`、`logs/` 和正在运行的生产 Agent 均不改动。

## 验证计划

1. 新增布局宽度、开关动画、滚轮手势锁和资源分隔比例测试。
2. 使用 `QT_QPA_PLATFORM=offscreen` 做日程与资源页无头渲染。
3. 运行 GUI 2.0 定向测试、完整 unittest 和 `compileall`。
4. 启动并关闭独立 GUI 2.0 预览做实机检查，不停止或替换生产版 Agent/GUI。

## 完成结果

- 日程首行已改为开关、时间、实例名同轴排列；卡片取消无业务意义的选中描边，常用按钮和导航不再显示默认虚线焦点框。
- 开关改为 140ms 乐观动画，保存失败会回滚；写盘仍使用原有单线程 override 队列。
- 触底扩展锁延长到 460ms，并在异步结果应用后清理排队的滚轮事件；连续同方向惯性输入不会在解锁后补滚。
- 日程与异常卡片使用同一套响应式宽度：普通窗口尽量使用可用空间，超宽窗口缓慢增长、居中并限制最大宽度；两处列表均关闭横向滚动条。
- 资源页图表与异常列表之间已改为可拖动分隔条，比例和当前二级页面会写入 `state/gui_state.json`。
- 折叠导航已使用 6 个本地线性 SVG 图标；PyInstaller 构建会带入图标目录，运行时兼容源码目录、单文件 `_MEI` 目录和 EXE 同级资源目录。
- 无头渲染检查覆盖 1800×940 和 2400×1300 两种窗口；125% / 150% 缩放定向测试通过。
- 完整回归共 175 项通过，`compileall` 通过，`git diff --check` 仅显示仓库既有的 LF/CRLF 提示，没有空白错误。
