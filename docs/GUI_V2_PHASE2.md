## 设计决定

### 共享进程快照

顶部状态栏现有 `ProcessService` 已经只做一次 `psutil.process_iter()`。本阶段在同一快照中补充磁盘和 Top 3 内存进程，再把不可变快照转发给总览，避免总览另起一次进程扫描。

### 总览刷新

- CPU / 内存 / 磁盘和 Top 3：沿用共享进程快照；总览可见时每 2 秒更新，其他页面只需每 4 秒更新顶部进程状态。
- 最近日志：只读取新增字节；总览可见时每 2 秒请求一次。
- 未来计划和当天资源趋势：后台读取并使用短周期签名，正常每 15 秒检查一次；页面不可见时不运行。
- “清空日志”只记录总览显示 cutoff，不删除文件，也不影响日志中心。
- 外层左右 `QSplitter` 和右侧上下 `QSplitter` 都保存到 `state/gui_state.json`。隐藏图表只隐藏图表，不隐藏最近事件。

### 公告中心

- 页面首次创建时只在后台读取本地 `state/news_monitor.json`，不联网。
- “增量更新”调用现有 `refresh_news_cache(..., full=False)`；“全部重拉”明确确认后调用 `full=True`。
- 更新前保存当前公告 cid、列表滚动值和正文滚动值；更新后优先恢复同一公告，不强制跳回第一条。
- 正文清洗、完整句摘要和 24:00 规范化继续复用 `news_monitor.py`，不复制第二套规则。

### 日志中心

- 后台 Worker 维护每个日志文件的 byte offset；正常刷新只读取文件末尾新增内容。
- 文件截断、替换或首次打开时才发送 reset 快照；普通刷新严禁清空整框重插。
- 页面内保留有限原始行缓存。切换过滤或搜索时可以从内存缓存重建显示，但不会重新读整文件。
- `QPlainTextEdit.setMaximumBlockCount()` 限制最多 5000 行；“暂停”只暂停自动滚底，不暂停后台尾追。

## 视觉与交互

- KPI 使用统一实色卡片和分色进度条，不加入玻璃、重阴影或额外依赖。
- 未来计划和公告列表使用 Model/View；宽屏按现有响应式卡片规则收住，窄屏不出现横向滚动条。
- 任何自动刷新都不改变用户当前页面、分栏、公告选中项或滚动位置。
- 常用鼠标按钮继续不显示 Windows 默认白色虚线焦点框。

## 175% 缩放边界

现有共享卡片布局测试原本覆盖 100% / 125% / 150%。本阶段把 175%（以 920px 基准对应 1610px 逻辑检查）加入边界用例，并额外以 `QT_SCALE_FACTOR=1.75` 运行关键无头渲染测试。175% 作为极端参考，不要求把信息密度强行维持在 100% 水平，但必须满足：无横向溢出、热区与绘制一致、按钮可达、文字不重叠。

## 验收标准

- 总览切换回来保留两个分隔条比例；图表折叠时最近事件仍可见；清空总览不改变日志文件。
- 公告异步更新期间界面可操作；回来后保留选中公告和滚动位置；全部重拉必须确认。
- 日志自动刷新只 append 新内容；文件截断能安全重置；过滤、搜索、暂停滚底、复制和打开文件可用。
- 页面隐藏或窗口最小化时，对应 UI 刷新定时器停止。
- 100% / 125% / 150% / 175% 布局测试、完整旧回归、`compileall` 和 Windows Actions 全部通过。
