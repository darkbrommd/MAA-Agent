# GUI 2.0 实机反馈修正说明（Phase 2.1）

本轮根据 2026-11-25 的实机截图修正 Phase 2，并提前接入少量与顶部状态直接相关的 Phase 3 能力。工作目录固定为 `D:\MAA-Agent_0920`；不修改旧版 `D:\MAA-Agent`、生产配置、生产状态、`app/agent.py`、VPN/代理或正在运行的 Agent/GUI。

## 本轮范围

1. 总览只保留“内存”主指标，移除 CPU、磁盘 KPI；空出的横向空间改为清楚的内存大户卡片，不再用一整行文字串联三个进程。
2. 顶部状态按 Agent、每个已配置 MAA 实例和 MuMu 分开显示；实例名称使用 `maa_instance_aliases`，单实例时不出现 MAA2。接入经过身份校验的“启动 / 停止 / 重启 Agent”，不提供模糊 PID 强杀。
3. 总览未来计划恢复可操作语义：显示实例别名、状态色和本次监督开关；开关只写一次性 skip override，不修改 MAA 自己的定时器。
4. 日程时间轴恢复自然日分隔标题；时间增大、加粗并在卡片高度内垂直居中。公告和其他列表禁用横向滚动条。
5. 公告正文读取继续复用现有缓存与清洗规则，但补强正文提取和不完整缓存重试；详情页优先展示完整正文，不把短摘要当成正文终点。
6. 左侧导航项目字号适当放大，折叠后的图标模式保持不变。
7. 资源白名单增加“正则匹配进程名”模式，例如 `.*GTAV.*`；保存前校验表达式，无效正则不得写入配置。旧的精确进程名和路径条目保持兼容。

## 安全边界

- Agent 启停复用 `agent_runtime.py` 的安装目录校验和停止握手；停止、重启均需在界面明确确认。
- MAA 实例“备注”按现有配置语义解释为 `maa_instance_aliases`（显示别名），本轮只读取和展示；编辑入口留在设置页迁移时完成，避免在多个页面各写一套配置保存。
- 资源正则只匹配进程名，不匹配完整命令行，避免意外吞掉无关程序；匹配忽略大小写。
- 公告测试使用合成 HTML / 本地缓存，不对官网做批量实测，不增加生产流量。

## 验收标准

- 总览顶部没有 CPU/磁盘卡，内存和 Top 3 进程在 100%–175% 缩放下无横向溢出。
- 顶部能直接看出 Agent、MAA1/MAA2（含别名）、MuMu 各自状态；Agent 控制不会误伤其他 Python 进程。
- 日程跨日时有清楚日期分隔，时间字号和垂直位置符合截图反馈；列表不出现水平滚动条。
- 公告正文合成回归覆盖多段正文、导航尾清洗和旧短缓存重拉判断。
- 正则白名单兼容旧配置，并有有效/无效表达式及匹配行为测试。
- 完整 unittest、175% GUI 专项、后台模式零 PySide6 导入和远端 Windows CI 通过。

## 实现结果（2026-11-25）

- 总览改为“内存总览 + Top 3 独立进程卡”，未来计划每行提供“关闭本次 / 恢复监测”按钮，不再把进程和操作挤成一条长文字。
- 顶部状态拆分为 Agent、每个 MAA 实例、MuMu；实例别名来自 `maa_instance_aliases`。启动、正常停止、重启均复用 `agent_runtime.py` 的安装身份校验，停止和重启需要确认。
- 时间轴每个自然日首项增加日期分隔，时间改为 19px 加粗并在卡片左侧垂直居中；公告列表和资源白名单列表禁用横向滚动条。
- 公告增量更新会补抓缓存里所有“有元数据但缺正文”的条目；全部重拉优先修复缺正文项；官网短 `brief` 与完整 `content`/`summary` 分开保存。定时轮询已经抓到的维护公告正文会直接写回缓存，不再丢弃。
- 资源白名单新增进程名正则模式，使用忽略大小写的完整匹配；部分匹配可写 `.*GTAV.*`。旧的路径/进程名精确匹配不变，无效正则在界面保存前拦截，在底层也安全地视为不匹配。
- 本地完整回归 188 项通过，175% GUI 专项 27 项通过，`compileall` 通过，后台入口导入检查确认未加载 PySide6。175% 离屏布局检查未见横向溢出；中文方框来自离屏 Qt 环境缺少字体，不是界面截字。

远端 Windows CI 结果在本轮提交推送后补记；本轮没有启动、停止或重启任何正在运行的生产进程。
