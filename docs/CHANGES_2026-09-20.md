## 本次最终修订重点

### 1. 日报开关与日报可靠性

- `disable_daily_report_today.bat`：只跳过当天日报，第二天自动恢复。
- `enable_daily_report.bat`：取消当天跳过；如果日报时间已经过去、今天尚未发送，Agent 会在下一轮补发。
- 日报不再依赖“恰好 23:50 那一分钟”。到点以后当天未发即可发送，并用 `state\daily_report_sent_date.txt` 防止 Agent 重启造成重复日报 / 重复 DeepSeek 调用。
- 正常日默认只发本地规则日报；只有存在未解决 incident、持续资源压力或长时间高 CPU 时才调用 DeepSeek。
- 当前 `deepseek-v4-flash` 配置保留。

### 2. MAA 定时任务监督重写

- 默认计划优先读取每个 MAA 的 `config\gui.new.json`，读取失败再尝试 `gui.new.json.bak`，两者均不可用才回退到 Agent `config.json` 的 `maa_schedule`。
- 支持 MAA 的半选 / 一次性 timer；短期计划快照用于处理 timer 启动后立即从配置里消失的情况。
- “计划跑过”主要依据 MAA 日志里的 `TaskChainStart` 实际时间，不再用日志文件 mtime 猜测。
- 启动匹配窗口至少覆盖整个 `scheduled_run_grace_minutes`，避免“15 分钟后实际启动、20 分钟时却被判漏跑”的矛盾。
- Agent 当时没有在线/没有完成开机宽限时，记为“未覆盖，不能判断”，不当成漏跑。
- 已经观测到的计划会从“未覆盖”账本移除，日报不会出现自相矛盾的统计。

### 3. 一次性计划 GUI / CLI

新增：

- `schedule_control.py`
- `schedule_control.bat`

用途是修改 **Agent 对这一轮计划的监督预期**：

- 跳过这一次：本次不判漏跑；
- 修改这一次预期时间：可改到同日或跨日；
- 撤销一次性例外。

GUI 会显示未来 72 小时，并保留过去 2 小时，方便事后补标记。move override 即使跨多天也不会因原始日期掉出窗口而失效。

重要边界：这个 GUI **不会偷偷热改正在运行的 MAA 本体定时器**。MAA 的真实长期执行时间仍应在 MAA 自己的“定时执行”里设置；Agent 会自动跟随。这样避免外部改 `gui.new.json` 后赌 MAA 是否热加载、或者为了改一次时间强杀/重启 MAA 的风险。

如果某个计划已经触发过“漏跑” incident，之后你在 GUI 里把它标记为 skip / move，Agent 下一轮会自动把旧 incident 结案。

### 4. MAA 错误通知降噪

- 不再使用“硬错误 / 软错误”作为 Bark 核心分类。
- Bark 统一说明：发生了什么 / 大概率原因 / 你要做什么。
- `SubTaskError`、`TaskChainStopped`、`CloseDown` 收尾异常等低价值事件默认静默并聚合计数。
- 普通 `TaskChainError`、ADB / 网络错误先进入 pending；只有错误后持续没有正常进展才 Bark。
- pending 的持续时间从“第一次尚未恢复的错误”开始算。连续每分钟报错不会再把计时器无限重置。
- 任意明确正常进展会把 pending 转为已恢复。
- 账号被顶 / 登录失效、版本更新 / 维护、初始化错误、崩溃等高置信信号仍可立即通知。

### 5. 进程 / 开机判断

- Windows 开机后默认 10 分钟不因 MAA 尚未拉起而报警。
- MAA 进程缺失需持续约 3 分钟才报警。
- 能可靠读取 exe 路径时可直接指出 MAA1 / MAA2；只要存在无法映射的 MAA 进程，就退回“总数判断”，避免误点名某个实例。
- 窗口“未响应”默认持续 2 分钟才报警。

### 6. 资源压力替代无意义 uptime 提醒

- 关闭 `enable_uptime_reminder`。
- RAM >= 88% 持续 30 分钟才进入普通压力判断。
- RAM >= 95% 且可用 <= 1.5 GB，持续 10 分钟属于严重压力。
- 同时判断 MAA / MuMu 是否异常膨胀，以及 GTA / Cyberpunk / Steam + 大型外部进程能否合理解释高内存。
- 日报记录 RAM P95 / 峰值 / 最低可用、CPU 平均 / P95 / 峰值 / 高负载时间、MAA / MuMu 峰值、磁盘空间和主要内存进程。
- 低价值异常改为“X 类 / 共 Y 次”聚合，不再把大量单次重试逐条堆进日报。
- 少数有意义但不必立即 Bark 的状态（游戏更新流程、资源完整性检查、掉线确认界面、执行次数达到上限等）以“额外观察”形式进入日报。

### 7. 代理、Bark 队列与外部 heartbeat

- 可自动读取 Windows 系统 HTTP/HTTPS 代理并通过该代理探测外网。
- 短抖动不报；默认持续失败约 10 分钟才 Bark。
- SOCKS-only 系统代理在未安装 PySocks 的情况下自动跳过，避免错误探测。
- Bark 离线队列每个主循环默认只重试 3 条，避免 100 条积压 × 12 秒超时把 watchdog 自己堵住十几分钟。
- “Bark 队列积压”不再通过 Bark 给 Bark 自己报警，只记本地状态 / 日报。
- `heartbeat_url` 仍为空；填入外部 heartbeat 服务后可覆盖“Windows 整机死机 / 断电 / 完全断网导致本机 Agent 也死亡”这种本机无法自报的场景。

## 安装

1. 先停止当前 Agent（原来的 `emergency_stop_agent.bat` 即可）。
2. 建议备份现有 `D:\MAA-Agent\agent.py` 和 `config.json`。
3. 把本补丁 ZIP 内文件复制到 `D:\MAA-Agent\`，覆盖同名文件。
4. **不要删除或覆盖你当前的 `.venv`、`state`、`logs`、`start_agent.bat`、`start_agent_hidden.vbs`、Copilot 通知 BAT。** 本补丁 ZIP 不包含这些运行中数据/原脚本。
5. 可先双击 `run_regression_tests.bat`。测试不会发送真实 Bark，也不会修改真实 MAA 配置。
6. 按原来的 `start_agent.bat` / `start_agent_hidden.vbs` 启动。

本版没有新增第三方 Python 依赖。你的现有 Python 3.14 venv 中已有 `psutil`、`requests`、`openai`、`pywin32`，可继续使用。
